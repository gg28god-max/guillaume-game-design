Home Run Derby VR

Developed in partnership with MLB for the All-Star Game Championship, Home Run Derby VR is a premium Meta Quest sports simulation. Serving as Lead Architect for the game's UI Visual Identity, the project required engineering a clean, high-performance design system — from typography and color palettes through button components, tournament UIs, first-time user experience flows, progression systems, and Season 3 interface updates.

03 — Art Brief

The Brief

Home Run Derby VR needed a UI that could carry a licensed MLB property into a headset without losing what makes it feel official, while still working as a genuinely usable VR interface. The brief below is what I held the whole system to.

Premise

A licensed MLB VR title for Meta Quest and SteamVR, developed at Little Guy Games in partnership with Major League Baseball for the All-Star Game Championship — arcade home run gameplay wrapped in a full live-service structure of prestige progression and seasonal tournaments.

Mood & Tone

Broadcast-sports energy — bold blues, gold, and red pulled straight from MLB's own brand system, built to read as a premium licensed product rather than an indie VR experiment.

Deliverables

As Lead UI Architect: typography and color system, button components, first-time user experience (controller onboarding and stance selection), the full tournament creation, lobby, and bracket flow, profile progression, and a Season 3 interface update to keep the system alive past launch.

Pipeline & Constraints

Figma for the design system, Photoshop for vector-based icons and text effects, every screen tested in-headset for readability and scale. Nothing could ship as a flat overlay — the whole system had to work as a floating 2D/3D spatial UI viewed at arm's length.

04 — The Problem

The Problem I Set Out to Solve

Designing for a controller, not a cursor

The first-time user flow has to teach a totally unfamiliar input method — point a laser at a graphic, pull a trigger — before the player has even swung a bat. The stance-selection screens show three distinct states (default, laser hovering, selected) because in VR, if the player doesn't know what's clickable, they're stuck before the game even starts.

A UI that still reads as MLB at arm's length

This is a licensed property, so brand fidelity to MLB's visual identity wasn't optional — but flat brand assets don't automatically hold up at VR viewing distance. Every typeface size and color choice was tested in-headset rather than on a monitor, so the interface would stay legible without diluting the license it was built to represent.

Building for a season, not a launch

Live player stats, ready-checks, and multi-round brackets meant the tournament UI had to handle real-time state, not just display static art. And a Season 3 interface update after launch meant the original design system had to be built extensible from day one, not patched together after the fact.

05 — The Approach

Designing Without a Cursor

Every flat-screen UX habit had to be re-examined for a headset: no hover, no right-click, no mouse precision — just a laser pointer, a trigger, and a player who can't see a menu bar because there isn't one. The process below is how I got from that constraint to a shipped, licensed MLB interface.

1. Empathize

In-headset walkthroughs with new VR players surfaced where a laser-and-trigger input model breaks down — mainly the moment before the player has learned what's clickable.

2. Define

Two constraints, in tension: MLB brand fidelity, and legibility at arm's length. Every subsequent design decision had to satisfy both at once, not trade one for the other.

3. Ideate

Built the design system directly in Figma as component states rather than static frames — every button, card, and icon exists as default, hovered, and selected from the start.

4. Prototype

Every screen went through multiple visible iteration passes — previous design kept side-by-side with the current pass and what actually shipped in-game, so regressions were obvious.

5. Test

Nothing was approved from a monitor. Every color, type size, and target size was reviewed in-headset, at the actual viewing distance a player would use it at.

VR Spatial UI Challenges

No hover, so state has to do the work

A cursor gives free feedback the moment it touches something. A VR laser gives none unless the UI builds it in — so every interactive element needed an explicit hover state distinct enough to read from across a room, not just up close.

Target size for a shaking hand, not a steady mouse

Hand tracking drifts. Buttons, cards, and mode-select tiles were sized and spaced with generous margin for aim error, especially in the first-time flow where the player is still learning to point at all.

Depth as a design constraint

Menus float in 3D space at a fixed distance from the player, so type sizes that work on a monitor can be unreadable in-headset and vice versa. Every panel was scaled and tested against the actual viewing distance, not a print-style hierarchy.

Color has to carry meaning, not just brand

Team colors, ready/not-ready states, and difficulty tiers all live in the same MLB blue-gold-red palette. Saturation and contrast had to separate 'this is a brand color' from 'this is a state you need to notice' without adding a second color language.

06 — Style Guide

One System, Every State Documented

Because nothing in VR gets a free hover state, every token in this system was defined as a set of explicit states — not just a color or a label. Agency FB carries the bold, condensed voice of broadcast sports typography; a single blue-gold-red palette runs from brand color through status color without switching languages; and every button, toggle, checkbox, and field is specified as Default, Hover, and Click so nothing shipped ambiguous.

Typeface

Agency FB, in Black Italic Bold Cap, Regular Cap, and Italic weights — one condensed sports-broadcast face carrying headers, body, and notification text alike.

Color

Black backgrounds, white strokes, and a blue/green/red button family — the same three hues double as status color for error, success, and loading fields.

Components

Buttons, toggles, checkboxes, fields, and notifications — every one specified in Default, Hover, and Click, so a designer or engineer never has to guess a missing state.

The full typographic scale and color token set, each swatch labeled with its hex value and where it's used.

Interactive components specified across all three states, from primary action buttons down to field validation.

08 — Test

Reviewed In-Headset, Not On a Monitor

This shipped as a live, MLB-partnered product rather than going through a formal external usability study — so validation took the form of a running heuristic review against VR-specific constraints, repeated at every iteration pass shown above.

Can you find it without hovering?

Every interactive element checked for a hover state that reads at laser-pointer distance, not just up close on a design file.

Can you hit it with a shaking hand?

Target sizes and spacing reviewed against realistic hand-tracking drift, especially in the first-time onboarding flow.

Does it still read as MLB, at distance?

Brand color and type checked in-headset for contrast and legibility, not approved from a flat monitor comp.

09 — Outcome

What Shipped, and What Held Up

Shipped for the All-Star Game

The full UI system launched as a licensed MLB product for the All-Star Game Championship on Meta Quest — brand-approved, not a fan project.

Extensible past launch

The Season 3 interface update reused the original design tokens and component states rather than requiring a rebuild — proof the system was architected to extend, not just to ship once.

A reusable VR UI language

Default, hover, and selected states, target sizing for hand-tracking drift, and distance-tested type became a system, not one-off screens — reusable for every mode added after launch.

10 — Reflection

What VR Taught Me About Flat UI

Designing without a cursor forces a kind of honesty that flat-screen UI can hide from: if a state isn't obvious without hovering, it isn't obvious. That constraint didn't just shape Home Run Derby VR — it's changed how I evaluate every interface I design since, VR or not.
